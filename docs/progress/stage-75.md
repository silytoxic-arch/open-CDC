# 阶段 75：按段解析驱动 —— 大型设计的 CDC 路径分析提速

日期：2026-11-09　版本：0.75.0

阶段 74 中，Corundum（ZCU106）的 CDC 路径分析需要约 46 秒，是整个分析中最慢的一步。这一阶段先测量瓶颈，再修正。CDC 结果完全不变。

## 1. 测量

前两次修改都是按猜测做的，没有效果：
- 第一次：在宽单元的逐位输入列表上按段解析驱动，反而变慢（56 秒）；
- 第二次：宽单元直接按信号块遍历输入，不再生成逐位列表，仍然是 46 秒。

于是在时序图构建中临时加入计数（已删除）：

| 计数 | 数值 |
|---|---|
| 寄存器引脚构建时间 | 37.9 秒（CDC 路径分析共 46 秒） |
| 整体求值的宽单元 | 13,267 个，输入共 5.1 亿位 |
| 按位求值的单元位 | 117 万个，输入共 3,755 万位 |
| 按段解析驱动的调用 | 5.1 亿次，**全部长度为 1** |

最后一行说明了原因：第一版 `driverRun` 只要设计中有三态焊盘就逐位处理，而 Corundum 有 I2C 焊盘。所以整个设计都没有按段解析，5.1 亿个输入位逐一查驱动。

## 2. 完成的功能

### 2.1 `DesignView::driverRun`

- 返回一个位的驱动，以及从它开始有多少个连续位的驱动是同一元素的连续位：同一寄存器、单元或端口，位号依次加一。
- 沿别名链只走一次。每一步把段长缩小到仍然连续的部分：
  - 驱动表项的范围；
  - 驱动信号中所在块的剩余位数；
  - 子实例端口的宽度。
- 安全措施：
  - 段的最后一位用逐位查找核对，不一致就退回单个位（同一位被多个表项驱动的情况）；
  - 只有**含三态焊盘的线网**逐位处理，其他线网不受影响。这是第一版的错误所在：只要设计中有焊盘就全部逐位处理。

### 2.2 时序图构建

- **整体求值的单元**（很宽的单元，或不按位计算的单元）：
  - 按输入信号块和驱动段遍历，不生成逐位列表；
  - 一段只取锥体需要的部分：宽驱动单元一次；其他来源取段的首位和末位（锥体本来就按来源合并为位区间）；窄驱动单元逐位。
  - 标志按输入决定：多路选择器的选择端、动态插入的下标、动态选择的下标是“选择”；反相器没有标志；其他是“逻辑”。与原来的逐位实现相同。
- **寄存器的数据引脚**：按块和段解析。
  - 同一宽单元驱动的一段，锥体相同，只解析一次；
  - 其他驱动直接得到每一位的驱动，不再逐位走别名链。

### 2.3 试过但没有保留的修改

- 常量函数调用的缓存：前端 25 秒中约 19 秒是 Corundum `lfsr_mask()` 的常量求值，约 2000 次，每次约 10 毫秒。
- 计划按函数、参数和实参缓存结果。测量结果是 0 次命中：每个调用的参数或实参都不同（不同的 CRC 宽度、不同的输出位）。
- 因此没有保留这项修改，前端时间仍由设计本身的常量函数决定。

## 3. 结果

Corundum ZCU106（Release 版本）：

| | 阶段 74 | 阶段 75 |
|---|---|---|
| 时序图寄存器引脚构建 | 37.9 秒 | 6.0 秒 |
| CDC 路径分析 | 46.2 秒 | 14.6 秒 |
| 整个分析 | 约 75 秒 | 约 43 秒 |
| 跨时钟路径与规则结果 | 219 / 209 / 10，规则命中相同 | 完全相同 |

其他 28 个 SV 项目的 CDC 结果逐行相同，VHDL 语料 48 个全部匹配。
