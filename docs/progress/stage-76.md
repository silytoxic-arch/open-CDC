# 阶段 76：Atari800_MiSTer —— 同值的两个驱动，consumersOf 按段处理

日期：2026-11-09　版本：0.76.0

阶段 75 的下一步是验证一个以 VHDL 为主的较大工程。这一阶段选择 **Atari800_MiSTer**（Atari 800/5200 核心）。它几乎全是 VHDL：87 个 VHDL 文件、4 个 Verilog 文件，包括 6502 处理器、ANTIC、GTIA、POKEY 和卡带仿真。

第一次分析有 1 个错误，整个设计无法分析。修复后能分析，但 CDC 路径分析需要 53 秒。测量后发现了第二个瓶颈，修复后整个分析约 7 秒。最终是 0 个错误、0 个锁存器、0 个未分析的构造，并加入了语料库。

## 1. 完成的功能

### 1.1 同值的两个驱动

```vhdl
SDRAM_WRITE_EN <= write_enable_next;            -- 并发赋值（address_decoder.vhdl:855）
process (...) begin ... SDRAM_WRITE_EN <= write_enable_next; ...   -- 组合进程中的默认值（第 1100 行）
```

- 同一个信号有两个驱动，但它们的值相同。Quartus 能编译这个核心。
- 以前 OpenCDC 报告多驱动错误（`IR-MULTIDRIVER`），整个设计无法分析。
- 以前只接受一种同值情况：两条完全相同的连续赋值（LiteX 生成这种代码）。
- 现在推广为：两个连接（连续赋值或进程），在重叠的每一位上源信号都相同，就是一个驱动。
  - 报告告警 `IR-SAME-DRIVERS`；
  - 两条完全相同的连续赋值仍然不报告，与以前一样。
- 反例测试：值不同时仍然是多驱动错误。
- 一个旧测试受到影响：`assign y = {a, b}; assign y[0] = b;`。两个驱动给 `y[0]` 的都是 `b`，按新规则是同值。
  - 这个测试的本意是冲突，所以第二个赋值改为 `a`，仍然检查多驱动错误；
  - 原来的写法改作 `IR-SAME-DRIVERS` 的正例。

### 1.2 consumersOf 按段处理

- 测量：CDC 路径分析的 53 秒中，几乎全部在 `SeqGraph::consumersOf`。这个函数在每次调用时扫描所有寄存器引脚位，设计中有 900 万个，主要是 RAM 数组寄存器。
- 修正：一段连续的引脚位如果源集合相同、且都不是直接连接，就只处理一次。产生的记录与原来逐位合并的结果完全相同。直接连接仍然逐位处理。
- 结果（Release 版本，输出除耗时外与修改前逐字节相同）：

| 工程 | CDC 路径分析（修改前 → 后） | 整个分析 |
|---|---|---|
| Atari800_MiSTer | 52.6 秒 → 4.8 秒 | 54 秒 → 7 秒 |
| Corundum ZCU106 | 14.6 秒 → 10.6 秒 | 43 秒 → 39 秒 |

- 同值判断只比较 IR 中的源信号位是否相同，不比较逻辑等价（例如 `a & b` 和 `b & a` 分别生成的两个单元）。
