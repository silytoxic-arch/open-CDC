# 阶段 23：重汇聚的门控与独热互斥

日期：2026-10-27　版本：0.23.0

## 1. 完成的功能

阶段 21 引入了按位的"标签族"：每个成员是"一次求值同时读到的同步器标签 + 成立条件"，条件矛盾的组合被丢弃。当时只有多路选择器会产生条件。本阶段增加两种互斥来源。

### 1.1 与门、或门的门控

`g & x` 在 `g = 0` 时恒为 0，与 `x` 无关（或门同理：`g = 1` 时恒为 1）。所以按门控输入 `g` 的取值，把所有求值划分为两种情形：
- `g` 单独决定输出：只读到 `g` 的标签；
- 另一输入通过：同时读到两边的标签，并带上 `g` 取另一值时推出的条件。

门控输入优先选不带标签的操作数（选择信号），其次选能推出条件的操作数。这是对全部情况的完整划分，只会去掉"输出不依赖某个输入"的那部分标签，是安全的。

按位归约（`|v`、`&v`）按逐位的二元运算链处理。因此能覆盖与或式选择器的常见写法：`(sel[0] & a) | (sel[1] & b)`、`|(sel & data)`。

### 1.2 至多一位为 1 的寄存器

如果一个寄存器（2 位及以上）的复位值，以及 D 输入能选到的所有值（经多路选择器的常量，或寄存器自身的保持值）都至多只有一位为 1，那么它的任意两位不可能在同一拍同时为 1。条件合并时会检查这种矛盾。

判定时会穿过连线，所以两段式状态机（`state <= next`，`next` 在组合 always 块里按 case 赋常量）也能识别。全零复位的独热选择寄存器同样适用。

`if (a) ... else if (b) ...` 这样的优先级链本身就是一个多路选择器，各分支早已互为备选，不需要额外处理。

## 2. 结果

- 与或式选择器加独热选择寄存器、与或式选择器加两段式独热状态机、归约写法：都不再报告重汇聚。
- 选择取自输入数据、某个分支会同时置两位、或额外有 `a2 & b2` 项时，仍然报告。
- 真实工程回归结果不变：两套语料库共 27 个工程加 13 个 FIFO。microwatt 的耗时没有增加。

## 3. 修改的文件

- `src/cdc/SeqGraph.{h,cpp}`：
  - `gated`：与/或门按门控输入划分求值；
  - And/Or/LogicAnd/LogicOr 与 ReduceOr/ReduceAnd 使用 `gated`；
  - `atMostOneHot`：至多一位为 1 的判定。
- `src/cdc/AdvancedAnalysis.cpp`：条件合并中加入独热矛盾检查，判定结果按寄存器缓存。
- `tests/cdc/test_cdc_advanced.cpp`：
  - 负例：独热选择、两段式独热状态机、归约写法；
  - 正例：任意选择（含归约写法）、会置两位的分支、额外的直接组合。
- 文档：`docs/rules/CDC-005.md`。

## 4. 测试有效性

把 `atMostOneHot` 改为一律返回 false 后，独热的两个负例失败。

## 5. 已知限制

- 下一状态需要计算才能得到的独热寄存器不能识别，例如移位 `sel <= {sel[0], sel[1]}`、译码 `1 << idx`。
- 依赖数据的互斥不能识别。
