# CDC-005: Reconvergence of independently synchronized signals

| Field | Value |
|---|---|
| Default severity | Warning |
| Result status | PotentialRisk. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc005`); facts from `src/cdc/AdvancedAnalysis.cpp` (`analyzeConvergence`) |
| Tests | `tests/cdc/test_cdc_advanced.cpp` (tag `[CDC-005]`), `examples/cdc_rules`, `examples/cdc_advanced` |

## Purpose
Find signals from one source clock domain that are synchronized separately and then combined again in the destination domain. Each synchronizer can resolve one destination cycle earlier or later than the other. Their combination can then see a state the source never had, for example `req && !abort` true for one cycle although the source changed both together.

## Applicability
Two or more recognized synchronizer chains (`two-flop`, `three-flop`, `multi-flop`, `toggle`, `gray`) that:
- have different first stages,
- have source clocks that are the same or synchronous (signals from unrelated source clocks are uncorrelated anyway), and
- meet in **one bit** of one destination register within `options.reconvergenceDepth` register levels (default 2) after the synchronizer outputs.

The following do not count as separate synchronizers:
- the bits of one Gray-coded or vector synchronizer (one path, one label);
- bits of one multi-bit source register that are split over separate synchronizers (CDC-008 reports those);
- reset bridges (synchronizers whose source flop has a constant data input).

## Detection algorithm (architecture §7.2)
1. Every chain's last stage gets the label of its path.
2. Level 0: the direct readers of the synchronizer outputs get the labels. Data pin bits are labeled per bit. Enable and synchronous-reset pins label the whole register, because they affect every bit.
3. Levels 1..K: labels propagate forward through registers of the destination clock. A reader of bits `[lo, hi]` of a register gets the labels of those bits plus the whole-register labels. At most 64 labels are kept per bit.
4. A register is a **meeting point** if one of its bits carries two labels whose paths qualify (see above). Propagation stops at the first meeting point, so each reconvergence is reported where it first happens.
   Before a bit counts as a meeting point, its label union is refined by walking the bit's combinational cone (`SeqGraph::dataAlternatives`). The walk computes which labels **one evaluation** reads together:
   - A multiplexer passes one data input at a time and always reads its select, so its data inputs are alternatives. Array selects are handled the same way.
   - Each alternative carries the register bit values that its select implies (through inverters, and/or, comparisons with constants, and muxes with a constant input such as `rreq_s = (raddr[13:8] == ID) ? rreq : 0`).
   - Combining alternatives whose conditions contradict (the same register bit, the same cycle, different values) is impossible, so those combinations are dropped. This covers the OR of several blocks' read data, each gated by its own address range.
   - `g & x` is 0 whenever the gate `g` is 0, whatever `x` is (`g | x` is 1 whenever `g` is 1): the evaluations are split by the gate's value, and where the gate decides alone only the gate is read. The gate is the operand without labels (a select), else one whose value implies facts. Reductions (`|v`, `&v`) are handled as chains of two-input operations. This covers AND-OR multiplexers, `(sel[0] & a) | (sel[1] & b)` and `|(sel & data)`.
   - A register that never holds more than one bit set contradicts two of its bits at 1 in the same cycle. Such a register has reset values, and values its data input can select (constants through multiplexers, or its own value, through wires such as a two-process FSM's `next`), with at most one bit set: one-hot state machines and one-hot selects.
   - Through a register, conditions move one cycle back. A register with an enable can hold an old value, so its conditions are dropped. A synchronous reset adds its reset value as an alternative.
   - The result never adds labels to the union found by the propagation.
   - Large families are merged conservatively: first members with the same labels (keeping only the conditions they share), then all members. Members subsumed by another (fewer labels, stronger conditions) are dropped.
   - Cones deeper than 48 logic levels, or beyond the evaluation budget, fall back to the plain union.

   This removes the register read-back pattern of the Analog Devices HDL library (`case (up_raddr)` over many synchronized status words, OR-ed across `up_adc_common`/`up_adc_channel` blocks). The pattern was reported before although only one word is read at a time.
5. Each involved path gets a `Reconvergence` record: register, location, depth, and the other paths. CDC-005 reports the first record and counts the rest.

Labels are bit-level so that packed status registers (`y <= {sa2, sb2}`), whose bits are never combined, are not reported.

## False-positive limits
- Logically independent signals that meet only because a register is shared (for example an XOR-ed observation register) are reported. Review and waive them.
- Consumers are aggregated per source bit range (hull). A reader of bits 0 and 3 of a register also counts as reading bits 1 and 2. The refinement above walks single bits, so a reported meeting point always has one bit that really reads both.
- Exclusivity is only proven from conditions on register values in the same cycle: comparisons with constants, gates, and registers that hold at most one bit set. A one-hot register whose next value is computed (a shift `sel <= {sel[0], sel[1]}`, a decoder `1 << idx`) is not recognized, and neither is data-dependent exclusivity; they stay reported. (Priority chains `if (a) ... else if (b)` are one multiplexer: their branches were alternatives already.)
- Meeting points deeper than K register levels, or behind outputs of the design, are not found.

## Test cases
- Positive: `y <= sa2 & sb2` (depth 0); `m1 <= sa2 & e; m2 <= m1 & e; y <= m2 | sb2` (depth 2, not found with `reconvergenceDepth = 1`); one source bit synchronized twice and XOR-ed (divergence).
- Negative: sources from unrelated clocks; packed register `{sa2, sb2}`; only one synchronizer used; register read-back with a `case` and an OR across blocks with exclusive address ranges, and a register copying it (`CDC-005 negative: register read-back …`).
- Positive next to the read-back: `y <= a2 & c2` is still reported, and so is the OR when both blocks decode the same address range.
- Negative: AND-OR multiplexer (also as a reduction) whose select is a one-hot register or a two-process one-hot FSM.
- Positive: the same multiplexer with a select loaded from input data, with a branch that sets two bits, or with an extra `a2 & b2` term.

## Fix
Synchronize related signals as one encoded value (Gray code), transfer them together with a handshake or asynchronous FIFO, or synchronize one qualifier and capture the other signals under it.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
