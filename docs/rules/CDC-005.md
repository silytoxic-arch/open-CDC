# CDC-005: Reconvergence of independently synchronized signals

| Field | Value |
|---|---|
| Default severity | Warning |
| Result status | PotentialRisk. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc005`); facts from `src/cdc/AdvancedAnalysis.cpp` (`analyzeConvergence`) |
| Tests | `tests/cdc/test_cdc_advanced.cpp` (tag `[CDC-005]`), `examples/cdc_rules`, `examples/cdc_advanced` |

## Purpose
Find signals from one source clock domain that are synchronized separately and then combined again in the destination domain. Each synchronizer can resolve one destination cycle earlier or later than the other. Their combination can then see a state the source never had, for example `req && !abort` true for one cycle although the source changed both together.

## Applicability
Two or more recognized synchronizer chains (`two-flop`, `three-flop`, `multi-flop`, `toggle`, `gray`) that:
- have different first stages,
- have source clocks that are the same or synchronous (signals from unrelated source clocks are uncorrelated anyway), and
- meet in **one bit** of one destination register within `options.reconvergenceDepth` register levels (default 2) after the synchronizer outputs.

The following do not count as separate synchronizers:
- the bits of one Gray-coded or vector synchronizer (one path, one label);
- bits of one multi-bit source register that are split over separate synchronizers (CDC-008 reports those);
- reset bridges (synchronizers whose source flop has a constant data input).

## Detection algorithm (architecture §7.2)
1. Every chain's last stage gets the label of its path.
2. Level 0: the direct readers of the synchronizer outputs get the labels. Data pin bits are labeled per bit. Enable and synchronous-reset pins label the whole register, because they affect every bit.
3. Levels 1..K: labels propagate forward through registers of the destination clock. A reader of bits `[lo, hi]` of a register gets the labels of those bits plus the whole-register labels. At most 64 labels are kept per bit.
4. A register is a **meeting point** if one of its bits carries two labels whose paths qualify (see above). Propagation stops at the first meeting point, so each reconvergence is reported where it first happens.
5. Each involved path gets a `Reconvergence` record: register, location, depth, and the other paths. CDC-005 reports the first record and counts the rest.

Labels are bit-level so that packed status registers (`y <= {sa2, sb2}`), whose bits are never combined, are not reported.

## False-positive limits
- Logically independent signals that meet only because a register is shared (for example an XOR-ed observation register) are reported. Review and waive them.
- Consumers are aggregated per source bit range (hull). A reader of bits 0 and 3 of a register also counts as reading bits 1 and 2.
- Meeting points deeper than K register levels, or behind outputs of the design, are not found.

## Test cases
- Positive: `y <= sa2 & sb2` (depth 0); `m1 <= sa2 & e; m2 <= m1 & e; y <= m2 | sb2` (depth 2, not found with `reconvergenceDepth = 1`); one source bit synchronized twice and XOR-ed (divergence).
- Negative: sources from unrelated clocks; packed register `{sa2, sb2}`; only one synchronizer used.

## Fix
Synchronize related signals as one encoded value (Gray code), transfer them together with a handshake or asynchronous FIFO, or synchronize one qualifier and capture the other signals under it.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
