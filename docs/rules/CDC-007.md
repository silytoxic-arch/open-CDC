# CDC-007: Pulse may be lost by a level synchronizer

| Field | Value |
|---|---|
| Default severity | Warning |
| Result status | PotentialRisk with clock periods; NeedsReview without. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc007`); facts from `src/cdc/AdvancedAnalysis.cpp` (`ProtocolRecognizer::mayPulse`) |
| Tests | `tests/cdc/test_cdc_advanced.cpp` (tag `[CDC-007]`), `examples/cdc_advanced` |

## Purpose
A flop-chain synchronizer samples a **level**. A pulse that is shorter than the destination clock period, plus setup/hold margin, can fall between two destination clock edges and be lost entirely.

## Applicability
A single-bit crossing synchronized by a flop chain (`two-flop`, `three-flop`, `multi-flop`, but not `toggle`) whose source register can be high for a single source cycle. That means it has no hold path:
- no enable pin (an enabled register keeps its value);
- no feedback from its own output (`f <= set ? 1 : f`);
- its next value is computed by logic. A register that only copies another register of the same clock inherits that register's verdict (up to 4 levels). A copy of a design input is not judged, because the input's waveform is unknown.

With both clock periods known (`create_clock` / `create_generated_clock`), the rule fires when `source period < 1.5 × destination period`. A one-source-cycle pulse is then not guaranteed to cover a destination edge with margin. Without periods it fires as NeedsReview.

## Detection algorithm
1. After chain recognition, every single-bit chain path whose source is a register that is neither a toggle flop nor a constant flop is checked with `mayPulse`.
2. The rule compares the clock periods from the clock model.

## False-positive limits
- A register without a hold path may still carry a stable level in practice (for example a decoded state that lasts many cycles). The rule cannot see such protocol guarantees.
- The 1.5 factor is a conservative margin for asynchronous clocks; it is not a proof. A slower source with long pulses is not reported.

## Test cases
- Positive: `p <= x & ~z` in a 10 ns clock synchronized into an 8 ns clock (PotentialRisk); the same without periods (NeedsReview).
- Negative: source period 20 ns versus 8 ns; a register with an enable; a plain copy of an input; a toggle synchronizer.

## Fix
Use a toggle (pulse) synchronizer: toggle a flop in the source domain per event, synchronize it, and detect edges in the destination domain. Alternatively, stretch the pulse in the source domain or use a handshake.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
