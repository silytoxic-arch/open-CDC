# CDC-004: Combinational logic in front of a synchronizer

| Field | Value |
|---|---|
| Default severity | Error |
| Result status | Violation. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc004`); facts from `src/cdc/CdcAnalyzer.cpp` (chain conditions) |
| Tests | `tests/cdc/test_cdc_advanced.cpp` (tag `[CDC-004]`), `tests/cdc/test_cdc.cpp`, `examples/cdc_rules` (case 9), `examples/cdc_advanced` |

## Purpose
Find synchronizer chains whose first stage receives the crossing through combinational logic. Logic glitches while its inputs change. The first stage can capture the glitch, and the synchronizer then passes it on as a valid pulse. Two inputs that change in the same source cycle can also produce a value that never existed in the source domain.

## Applicability
A recognized flop chain (`two-flop`, `three-flop`, `multi-flop`, `toggle` or `gray`) of at least two stages, where the condition "the crossing enters the first stage without glitch-prone combinational logic" failed.

Logic is glitch-prone when a destination bit of the first stage depends on **two or more asynchronous bits**. Asynchronous bits are bits of sources whose clock is not the destination clock or synchronous to it, including sources without a clock. Examples: `a & c` with both from `clk_a`, a decode `a_bus == 3`, or `a | c` from two clocks.

Logic whose only other inputs are destination-clock signals or constants is accepted, with a note. Examples are an enable gate `g & {4{en}}` and a clear gate. Such a destination signal changes only right after a destination clock edge, so the output changes only when the one asynchronous input changes: it cannot glitch. (A named clear such as `if (clr) s1 <= 0` becomes a synchronous reset pin in the IR and is not logic at all.) Wires and inverters are not logic.

## Detection algorithm
1. While crossings are collected, every destination bit records whether all of its sources arrive by wire or inverter (`SeqGraph::BitInput::direct*`, `kLogic` flag).
2. For paths through logic, the asynchronous source bits of every destination bit are counted from the cone (bit hulls). Exactly one per bit means gating by destination-clock logic, so the condition holds.
3. Chain recognition (CDC-002) builds the chain regardless of the logic and records the outcome.
4. CDC-004 fires for chain paths of two or more stages with that failed condition. The message names the first logic cell on the reconstructed path.

## False-positive limits
- Logic whose inputs are all quasi-static (configuration written while the clocks are stopped) is reported too. Accept such hits with a waiver ([docs/waivers.md](../waivers.md)).
- Counting uses bit hulls of the cone, so a hull that covers unused bits can count too many asynchronous bits (conservative).
- Logic **between** two stages breaks the chain. It is then reported as a single-stage synchronizer (CDC-002), not as CDC-004.
- An inverter is allowed. A buffer is a wire in the IR.

## Test cases
- Positive: `s1 <= a & c; s2 <= s1;`, and `s1 <= a_p | a_q` in `examples/cdc_rules` (case 9).
- Positive: `s1 <= a == 2'd3` (two bits of one source decoded).
- Negative: `s1 <= a;` and `n1 <= ~a;` followed by a second stage; `s1 <= g & {4{en}}` with `en` in the destination clock (the verilog-axis frame FIFO clears its first pointer stage this way).

## Fix
Register the combined signal in the source clock domain and synchronize that register's output. Keep only wires (or one inverter) between the source flop and the first synchronizer stage.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
