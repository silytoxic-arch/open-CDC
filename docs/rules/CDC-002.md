# CDC-002: Crossing passes only one synchronizer stage

| Field | Value |
|---|---|
| Default severity | Warning |
| Result status | Violation. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc002`) |
| Tests | `tests/cdc/test_cdc.cpp` (tag `[CDC-002]`), `examples/cdc_rules` |

## Purpose
Find single-bit crossings that are captured by a flop chain that is too short. One stage leaves too little time for metastability to resolve before the value is used.

## Applicability
Single-bit crossings between asynchronous clocks, or clocks with an unknown relation, where either:
- the destination register samples the crossing directly (plain wire or inverter, no logic), and the flop chain is shorter than `options.minSyncStages` (default 2), or the register's output goes into logic instead of a second stage; or
- a chain of two or more stages exists, but its **first stage also drives other logic**. Those readers only see one stage.

## Detection algorithm
1. Chains are followed from the destination bit. A next stage is a register in the same clock domain and on the same edge whose data input is a plain wire (or inverter) from the current stage bit. The chain may cross the hierarchy, for example into a `sync_2ff` module. Readers are found with `SeqGraph::consumersOf`.
2. A stage that is also read by other logic, once at least `minSyncStages` stages exist, is the synchronizer output and ends the chain. In `s1 -> s2 -> s3; pulse = s2 ^ s3`, s3 is an edge-detector delay, not a third stage. Crossings into asynchronous reset pins are judged by CDC-006 only.
3. Stage count 1 gives `single-flop`. Two or more gives `two-flop`, `three-flop` or `multi-flop`. Any other reader of a stage is recorded as a failed condition.
4. CDC-002 fires when `width == 1` and either the type is `single-flop` (or the chain is shorter than `minSyncStages`), or the condition "the first stage drives only the second stage" failed.

## False-positive limits
- Very slow destination clocks can make one stage sufficient. Set `minSyncStages: 1` or review the path.
- A first stage that also drives an output port is not counted as extra fanout. Only register inputs are counted.

## Test cases
- Positive: `s1 <= a; y <= s1 ^ b;` (one stage), and a two-stage chain whose first stage also feeds logic.
- Negative: a clean two-flop chain, a three-flop chain, and a two-flop chain inside a separate module.

## Fix
Add a second register stage in the destination domain, use only the last stage, and do not tap the first stage.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
