# CDC-006: Asynchronous reset released without a reset synchronizer

| Field | Value |
|---|---|
| Default severity | Error |
| Result status | Violation if the reset comes from another clock domain or the reset synchronizer fails a condition. PotentialRisk if it comes from an input or black box without a clock domain. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc006`); facts from `src/cdc/AdvancedAnalysis.cpp` (`findResetSynchronizers`, `classifyResetPaths`) and `CdcAnalyzer.cpp` (`addResetPath`) |
| Tests | `tests/cdc/test_cdc_advanced.cpp` (tag `[CDC-006]`), smoke and async_fifo examples, `examples/cdc_advanced` |

## Purpose
Assertion of an asynchronous reset may be asynchronous. Its **release** must be synchronous to the clock of the registers it resets. A release close to a clock edge violates recovery/removal timing. Registers can go metastable, or leave reset in different cycles, so a state machine starts in an illegal state.

## Applicability
A register whose asynchronous reset pin is driven by:
- a register of another clock domain (asynchronous or unknown relation): **Violation**;
- a design input or black-box output without a clock domain: **PotentialRisk** (external resets are asynchronous to every clock unless declared otherwise);

unless the register is a stage of a recognized **reset synchronizer** for its own clock. A reset synchronizer whose necessary conditions fail is also reported (Violation).

An input declared with `set_input_delay -clock <clk>` belongs to that clock. It is then not a crossing for registers of that clock: this is how a reset synchronized outside the design is declared.

## Reset synchronizer recognition
Flops of one clock and edge that:
1. start with a stage whose data input is constant (no enable, no synchronous reset), with an asynchronous reset;
2. continue through stages that copy the previous stage by wire or inverter and **share the same asynchronous reset sources** (`r2 <= r1`, also inside one vector register: `{r2, r1} <= {r1, 1'b1}`).

Conditions checked: constant first-stage data; shared reset; at least `minSyncStages` stages; stages before the last drive only the next stage; same clock and edge. A lone constant flop counts only if it drives asynchronous resets. The number of registers reset by the last stage is reported.

## Detection algorithm
1. Before crossings are collected, the reset synchronizers are recognized (level-wise consumer queries).
2. Crossings into asynchronous reset pins become paths, grouped per (reset source, destination clock, reset synchronizer). `groupSize` and the first members are kept, because one external reset typically resets thousands of registers. The fingerprint of an ungrouped path names the source and destination clock, so it stays stable when registers are added.
3. A grouped path whose destination is a reset-synchronizer stage gets type `reset-sync`. Its status follows the conditions.
4. CDC-006 fires for reset paths that are not `reset-sync`, and for `reset-sync` paths whose conditions failed. A note says when the source is a reset synchronizer of another clock ("needs its own reset synchronizer").

Rules CDC-001/002/003 do not judge asynchronous reset pins.

## False-positive limits
- External resets that are already synchronized outside the design are reported until they are declared with `set_input_delay -clock`.
- Reset bridges built from a constant-D flop in the source domain followed by a plain synchronizer in the destination domain (the stage-4 "reset bridge" note) are data paths. They are not reported here.
- Resets of registers whose clock could not be resolved are not checked (CDC-NO-DOMAIN).

## Test cases
- Negative: a 2-stage reset synchronizer (`{r2, r1} <= {r1, 1'b1}`) whose output resets another register; an input declared with `set_input_delay -clock`.
- Positive: external reset used directly (2 registers, one grouped path); reset from a `clk_a` register used in `clk_b`; reset synchronized for `clk_a` but used in `clk_b`; single-stage reset synchronizer.

## Fix
Add a reset synchronizer per clock domain: two or more flops clocked by that clock, asynchronously reset by the raw reset, shifting in a constant (1 for active-low). Use its output as the asynchronous reset of that domain's registers.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
