# CDC-009: Crossing logic mixes signals from several clock domains

| Field | Value |
|---|---|
| Default severity | Warning |
| Result status | PotentialRisk. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc009`); facts from `src/cdc/AdvancedAnalysis.cpp` (`analyzeConvergence`, `mixedClocks`) |
| Tests | `tests/cdc/test_cdc_advanced.cpp` (tag `[CDC-009]`), `examples/cdc_advanced` |

## Purpose
Combinational logic on a crossing that combines signals from two or more foreign clock domains can glitch whenever any of them changes. No single source domain controls when the result is stable, so neither source-domain registering nor a protocol can make the combination safe.

## Applicability
A crossing that passes combinational logic (not only wires and inverters) whose inputs also include sources from another clock. That clock is asynchronous or of unknown relation both to the destination clock and to this crossing's source clock. The crossing must otherwise be synchronized or qualified. Unsynchronized crossings are already reported by CDC-001/CDC-003, so CDC-009 is suppressed for synchronizer type `none` and `single-flop`.

## Detection algorithm
For every crossing path through logic, the cone of each destination pin bit is scanned (`SeqGraph` source sets). The clocks of the other sources are collected when they cross into the destination and are unrelated to the path's source clock. The names are stored in `CdcPath::mixedClocks`.

## False-positive limits
- Mixing with signals of the destination clock is not reported here. A logic gate in front of a synchronizer is CDC-004.
- Sources whose clock is unknown (no domain) are not counted.

## Test cases
- Positive: `s1 <= a | c` with `a` in `clk_a`, `c` in `clk_c`, synchronized into `clk_b` (CDC-004 and CDC-009 on both paths).
- Negative: `s1 <= a & en` with `en` in the destination clock (CDC-004 only); `y <= a | c` without a synchronizer (CDC-001 only).

## Fix
Synchronize each source domain's signal separately into the destination domain and combine the synchronized signals there (and check them for reconvergence, CDC-005).

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
