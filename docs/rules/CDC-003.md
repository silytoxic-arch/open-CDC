# CDC-003: Multi-bit data crosses clock domains without synchronization

| Field | Value |
|---|---|
| Default severity | Error |
| Result status | Violation. If the clock relation is unknown, it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc003`) |
| Tests | `tests/cdc/test_cdc.cpp` (tag `[CDC-003]`), `examples/cdc_rules` |

## Purpose
Find multi-bit values captured in another clock domain without any protection. Each bit can resolve in a different destination cycle, so the destination can see a value that never existed in the source (data incoherency).

## Applicability
Crossings with more than one bit (`width = max(source bits, destination bits) > 1`) between asynchronous clocks, or clocks with an unknown relation, that are neither:
- **synchronized bit by bit** by flop chains (those are checked by CDC-008, Gray/coherency, in stage 5), nor
- **qualified data**: captured while an enable or select of the destination is driven by a synchronized control signal from the same source clock.

## Stage-5 note
Crossings into asynchronous reset pins are judged by CDC-006 only, not by this rule.

## Detection algorithm
1. Crossing paths are found and grouped as described in CDC-001.
2. Qualifier search (`CdcAnalyzer::findQualifier`) starts from the destination register's control sources: its clock-enable and sync-reset inputs, plus data-input sources that arrive through a mux select or an array index. It looks for a register that is stage 2 or later of a recognized synchronizer, following registered control logic in the destination domain for up to `maxQualifierDepth` (2) register levels. That synchronizer's source clock must be the same as, or synchronous to, the data's source clock.
3. CDC-003 fires on paths with `width > 1` and `synchronizerType` of `none` or `single-flop`.

## False-positive limits
- A qualifier that is synchronized more than two register levels away from the destination enable is not found, so the path is reported.
- The rule does not check that the data is actually stable while the qualifier is active. Qualified paths are marked `protocol-unverified` and list that condition.

## Test cases
- Positive: `b_bus <= a_bus` (8 bits, no qualifier), and a memory written in one domain and read into a register of another domain.
- Negative: the same bus captured under `if (valid_sync)` where `valid_sync` is a two-flop synchronized valid from the source clock, a bus synchronized bit by bit, and the bus between synchronous clocks.

## Fix
Use a handshake or MUX synchronizer (capture under an enable driven by a synchronized request), an asynchronous FIFO, or Gray-code the value if it is a counter.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
