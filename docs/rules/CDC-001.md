# CDC-001: Single-bit signal crosses clock domains without a synchronizer

| Field | Value |
|---|---|
| Default severity | Error |
| Result status | Violation. If the clock relation is unknown (policy `report`), it becomes NeedsReview |
| Implemented in | `src/rules/RuleEngine.cpp` (`Cdc001`) |
| Tests | `tests/cdc/test_cdc.cpp` (tag `[CDC-001]`), `examples/cdc_rules` |

## Purpose
Find single-bit crossings that reach a destination register without any synchronizer. A destination flop that samples an asynchronous signal can go metastable. If the signal also passes combinational logic first, glitches from that logic can be sampled as well.

## Applicability
A path qualifies when all of the following hold:
- the source and destination clocks are **asynchronous**, or their relation is **unknown** and the policy is not `assume_sync`;
- the path is single-bit: one source bit and one destination bit;
- no synchronizer was recognized (`synchronizerType = none`). That means one of:
  - the crossing enters the destination register **through combinational logic**, and the register does not start a flop chain;
  - the crossing enters the register's **clock-enable** or **synchronous-reset** input.

## Stage-5 note
Crossings into asynchronous reset pins are judged by CDC-006 only, not by this rule.

## Detection algorithm
1. The sequential dependency graph (`SeqGraph`) gives the upstream sources of every register input bit. It follows aliases, port connections and combinational cells across the hierarchy.
2. For each (source, destination register, input pin) group, the clock relation of the two domains decides whether the group is a crossing (`CdcAnalyzer::findCrossings`).
3. Synchronizer recognition runs first: flop chains, then qualified data, then single flops. Paths for which none is found keep `synchronizerType = none`.
4. CDC-001 fires on paths with `width == 1` and `synchronizerType == none`.

## False-positive limits
- Quasi-static signals (for example configuration written once while the destination clock is stopped) are reported too. Accept them with a waiver ([docs/waivers.md](../waivers.md)).
- Input ports only take part when `set_input_delay -clock` assigns them a domain. Unclocked inputs are reported as `CDC-NO-DOMAIN` instead.
- Asynchronous reset inputs are not checked here. They are checked by CDC-006 (stage 5).

## Test cases
- Positive: `q <= a_async & b_local` (logic before the destination), and a crossing into an enable pin (`if (a_async) cnt <= cnt + 1`).
- Negative: the same crossing through a two-flop synchronizer, the same design with synchronous clocks (one generated from the other), and with clocks declared exclusive.

## Fix
Add a two-flop synchronizer: two registers in series in the destination domain, marked `ASYNC_REG`, and use only the last stage. Register the signal in the source domain first so that no combinational logic precedes the synchronizer.

## Waivers
A reviewed hit of this rule can be waived by rule id, path fingerprint, or source/destination name (see [docs/waivers.md](../waivers.md)). A waived hit stays in all reports, marked with its waiver, and no longer counts as a violation.
