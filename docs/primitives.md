# Built-in vendor primitive models

OpenCDC models the FPGA vendor primitives that matter for clock-domain-crossing analysis. A model is added to the compilation only when the design instantiates the primitive and the sources do not define a module of that name; a user module of the same name always wins. The models describe register-transfer structure (which pins are clocks, which signals are registered in which clock, which outputs have no clock domain), not the full functional behavior. They are therefore not usable for simulation.

Common rules:

- Parameters a model does not use are accepted and ignored. VHDL aggregates without a type (for example `INIT_00 => (others => '0')`) are skipped.
- A connection to a pin the model does not have is reported once per pin as `FE-PRIMITIVE-PORT` (information) and ignored. This applies to cascade, ECC, sleep and test pins.
- Unconnected inputs and outputs of primitives are not reported.
- `ASYNC_REG` on an instance (Verilog attribute, or VHDL `attribute ASYNC_REG of s1 : label is "TRUE"`) marks a synchronizer stage.
- VHDL designs reach the models through:
  - `library unisim; use unisim.vcomponents.all;`
  - `library xpm; use xpm.vcomponents.all;`
  - `library altera_mf; use altera_mf.altera_mf_components.all;`
  - Lattice: `library ecp5u; use ecp5u.components.all;` (also `ecp5um`, `ecp5um5g`), `library sb_ice40_components_syn; use sb_ice40_components_syn.components.all;` (iCEcube2) and `library iCE40UP; use iCE40UP.components.all;` (Radiant);
  - Gowin: `library gw1n; use gw1n.components.all;` (also `gw1nr`, `gw1ns`, `gw1nz`, `gw2a`, `gw2ar`, `gw5a`, `gw5ast`).
- A component package is added only for a library the VHDL code names and the project does not provide itself.
- "No clock domain" means the signal is driven by the internal black box `opencdc_async_source`. Such a signal used as an asynchronous reset is checked by CDC-006. As data, it is listed as `CDC-NO-DOMAIN` and not checked.

Sources:
- `src/frontend/primitives/*.v` (Verilog models) and `*.vhd` (component packages);
- MMCM/PLL models are generated per use in `src/frontend/Primitives.cpp`;
- GT models are generated by `tools/primitives/gen_gt.py`.

## Not modelled

These primitives are still reported as `FE-UNKNOWN-MODULE`:
- Xilinx: `PCIE*`, `CMAC*`, `HBM*`;
- Intel: transceiver IP other than the Arria V / Cyclone V Native PHY (Arria 10 and later, PHY IP such as the 10GBASE-R PHY), `altlvds`, `altiobuf`;
- Lattice: SERDES (`DCUA`), gearing DDR (`IDDRX2F`, `ODDRX2F`, …), `PDPW16KD`; Gowin: `IDDR`/`ODDR` (name clash with Xilinx), `SP`, `pROM`, SERDES; Microchip: `CCC` and the PolarFire transceivers and I/O cells.

For each one you can:
- provide your own behavioral model in the sources (it replaces the built-in lookup), or
- leave it as an unresolved instance, which is analyzed conservatively and listed as `IR-UNRESOLVED-INSTANCE`.
